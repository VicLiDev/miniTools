# 05.cfg 配置工具速览

一个 Python CLI + 一个 Bash 包装层，统一读写 INI / JSON / YAML / XML。
核心实现拆在 `00.libs/cfg_tool/` 包里，`00.libs/05.cfg.py` 只是入口。

## 1. 五分钟路线

按这个顺序看，最快建立整体印象：

| 顺序 | 文件                         | 看什么                                           |
|------|------------------------------|--------------------------------------------------|
| 1    | `00.libs/05.cfg.py`          | 入口：解析真实路径、调用 `cfg_tool.cli.main`     |
| 2    | `00.libs/cfg_tool/cli.py`    | 格式分发：按需导入对应适配器                     |
| 3    | `00.libs/cfg_tool/common.py` | 共享工具：JSON Pointer、备份开关、标量格式化     |
| 4    | `00.libs/cfg_tool/json.py`   | 适配器模板：`load/get/set/delete/save/validate`  |
| 5    | `00.libs/05.cfg.sh`          | Bash API：`cfg_*` 与 `ini_*/json_*/yaml_*/xml_*` |
| 6    | `00.libs/05.cfg_demo.sh`     | 可执行的行为说明：147 个测试按格式分组           |


## 2. 目录结构

```text
00.libs/
├── 05.cfg.py             入口（约 100 行）
├── 05.cfg.sh             Bash API
├── 05.cfg_demo.sh        自测（147 个用例）
└── cfg_tool/
    ├── __init__.py       包说明
    ├── cli.py            总帮助与格式分发
    ├── common.py         共享工具
    ├── ini.py            INI 适配器
    ├── json.py           JSON 适配器
    ├── yaml.py           YAML 适配器
    └── xml.py            XML 适配器
```

各模块职责：

| 文件                 | 职责                          | 关键对象                          |
|----------------------|-------------------------------|-----------------------------------|
| `05.cfg.py`          | 入口，处理软链接              | `main`                            |
| `cfg_tool/cli.py`    | 解析 `<format>`，懒加载适配器 | `CFG_USAGE`、`main`               |
| `cfg_tool/common.py` | 指针解析、备份开关、标量输出  | `parse_pointer`、`backup_enabled` |
| `cfg_tool/ini.py`    | 保留原行序的 INI 读写         | `IniFile`、`_ini_main`            |
| `cfg_tool/json.py`   | 标准库 JSON，整体重排         | `JsonFile`、`_json_main`          |
| `cfg_tool/yaml.py`   | ruamel 往返，保留注释/顺序    | `YamlFile`、`_yaml_main`          |
| `cfg_tool/xml.py`    | lxml + XPath，保留 XML 结构   | `XmlFile`、`_xml_main`            |

## 3. 调用链

```text
业务脚本
  └─ cfg_get json file /server/port        # source 05.cfg.sh
       └─ _cfg_run json get ...            # python3 05.cfg.py
            └─ cfg_tool.cli.main()         # 只导入选中的格式
                 └─ cfg_tool.json._json_main()
                      └─ JsonFile.load / get
```

写操作多一步统一保存：

```text
set -> 修改内存 -> save()
  -> 同目录临时文件 -> 可选 .bak -> os.replace() 原子替换
```

## 4. 适配器共同骨架

四个格式的类都提供同一组方法，新增格式时照着实现即可：

| 方法                           | 作用                           |
|--------------------------------|--------------------------------|
| `load(path, create=False)`     | 读取文件；缺失时按需创建空文档 |
| `get(path, default)`           | 取单个值，缺失抛 `KeyError`    |
| `get_all(path)`                | 取全部匹配值                   |
| `has(path)`                    | 是否存在                       |
| `set(path, value, if_missing)` | 写入，必要时创建中间节点       |
| `delete(path)`                 | 删除                           |
| `keys(path)`                   | 列出子键（INI/JSON/YAML）      |
| `save(backup)`                 | 原子写回，保留权限/软链接      |
| `validate()`                   | 返回 `(errors, warnings)`      |

每个模块再提供 `*_USAGE`、错误前缀（`ini:` / `json:` / ...）和 `_*_main` 分发函数。

## 5. 命令速查

### 5.1 通用 Bash API

```bash
cfg_get          <fmt> <file> <path> [flags]
cfg_get_default  <fmt> <file> <path> <default> [flags]
cfg_get_all      <fmt> <file> <path> [flags]
cfg_has          <fmt> <file> <path>
cfg_set          <fmt> <file> <path> <value> [flags]
cfg_set_if_missing <fmt> <file> <path> <value> [flags]
cfg_del          <fmt> <file> <path>
cfg_del_section  <fmt> <file> <path>          # ini only
cfg_sections     <fmt> <file>                 # ini only
cfg_keys         <fmt> <file> <path>
cfg_entries      <fmt> <file> [path]          # ini only
cfg_numbered     <fmt> <file> <path>          # ini only
cfg_validate     <fmt> <file>
cfg_run          <fmt> <command> [args...]
```

格式专用包装：

```bash
ini_get / ini_set / ini_del / ini_sections ...
json_get / json_set / json_del / json_keys ...
yaml_get / yaml_set / yaml_del / yaml_keys ...
xml_get / xml_set / xml_set_attr / xml_add / xml_replace ...
```

### 5.2 路径规则

| 格式 | 路径写法              | 示例                       |
|------|-----------------------|----------------------------|
| INI  | `/section/key`        | `/platform/name`           |
| JSON | RFC 6901 JSON Pointer | `/server/port`、`/items/0` |
| YAML | 同 JSON Pointer       | `/server/tls`              |
| XML  | XPath                 | `/config/item[1]/@id`      |

XML 命名空间用可重复的 `--ns prefix=uri`；默认命名空间也要显式给前缀。

### 5.3 格式命令矩阵

| 操作                                        | INI | JSON | YAML | XML |
|---------------------------------------------|-----|------|------|-----|
| get / get-default / get-all / has           | 是  | 是   | 是   | 是  |
| set / del                                   | 是  | 是   | 是   | 是  |
| set-if-missing                              | 是  | 是   | 是   | 否  |
| keys                                        | 是  | 是   | 是   | 否  |
| sections / entries / numbered / del-section | 是  | 否   | 否   | 否  |
| set-attr / add / replace                    | 否  | 否   | 否   | 是  |
| validate                                    | 是  | 是   | 是   | 是  |

## 6. 最小示例

### 6.1 INI

```bash
printf '[platform]\nname = rk3588\narch = arm64\n' > /tmp/demo.ini
python3 00.libs/05.cfg.py ini get /tmp/demo.ini platform name
python3 00.libs/05.cfg.py ini set /tmp/demo.ini platform arch arm64
```

### 6.2 JSON

```bash
printf '{"server":{"host":"localhost","port":8080}}\n' > /tmp/demo.json
python3 00.libs/05.cfg.py json get /tmp/demo.json /server/port
python3 00.libs/05.cfg.py json set /tmp/demo.json /server/port 9090 --json
```

### 6.3 YAML

```bash
cat > /tmp/demo.yaml <<'EOF'
server:
  host: localhost
  tls: true
EOF
python3 00.libs/05.cfg.py yaml get /tmp/demo.yaml /server/tls
python3 00.libs/05.cfg.py yaml set /tmp/demo.yaml /server/tls false --yaml
```

无 `--yaml` 时，`set` 的值按字符串写入；需要数字/布尔/null 时加 `--yaml`。

### 6.4 XML

```bash
cat > /tmp/demo.xml <<'EOF'
<config>
  <item id="1">one</item>
  <item id="2">two</item>
</config>
EOF
python3 00.libs/05.cfg.py xml get /tmp/demo.xml '/config/item[1]/@id'
python3 00.libs/05.cfg.py xml set /tmp/demo.xml '/config/item[2]' TWO
```

### 6.5 在 Bash 脚本里用

`05.cfg.sh` 依赖 `BASH_SOURCE`，必须在 Bash 下 `source`（zsh 不支持）：

```bash
source 00.libs/05.cfg.sh
cfg_get json /tmp/demo.json /server/port
json_set /tmp/demo.json /server/port 9090 --json
```

执行过 `init_tools.sh` 后可以用安装路径：

```bash
source ~/bin/_cfg.sh
python3 ~/bin/_cfg.py json get /tmp/demo.json /server/port
```

## 7. 设计约定

| 项目   | 约定                                                   |
|--------|--------------------------------------------------------|
| INI    | 按行保留注释、空行、顺序；重复 key 读取取最后一个      |
| JSON   | 写入时整体重排；自动识别 2/4/8 空格或 Tab 缩进         |
| YAML   | ruamel 往返，保留注释、key 顺序、引号风格              |
| XML    | lxml，保留注释、CDATA、声明、doctype、空白             |
| 写入   | 临时文件 + `os.replace` 原子替换；解析软链接目标       |
| 备份   | `CFG_BACKUP=1` 或 `INI_BACKUP=1` 生成 `<file>.bak`     |
| 退出码 | `0` 成功/找到；`1` 未找到；`2` 用法/IO/解析/依赖错误   |
| 依赖   | Python 3.10+；YAML 需要 `ruamel.yaml`，XML 需要 `lxml` |
| 降级   | YAML/XML 依赖缺失直接报错，不做有损降级                |

XML 的 `set`/`add` 不会自动创建缺失文件或元素；需要先保证文件存在。
XML 的 `set` 只改文本，`set --xml` 才会替换子节点。

## 8. 验证与调试

```bash
python3 -m py_compile 00.libs/05.cfg.py 00.libs/cfg_tool/*.py
bash -n 00.libs/05.cfg.sh 00.libs/05.cfg_demo.sh init_tools.sh
bash 00.libs/05.cfg_demo.sh
```

自测脚本按格式组织：

```text
json_setup / json_test_read / json_test_write / json_test_edge / json_test_cli
yaml_setup / yaml_test_read / yaml_test_write / yaml_test_edge / yaml_test_cli
xml_setup  / xml_test_read  / xml_test_write  / xml_test_preserve
xml_test_namespaces / xml_test_edge / xml_test_cli
ini_setup  / ini_test_read  / ini_test_write  / ini_test_edge / ini_test_cli
run_json / run_yaml / run_xml / run_ini -> main -> summary
```

单看某个格式的行为，直接读对应的 `*_test_*` 函数即可；每个 `chk` 就是一条规格。

## 9. 新增一种格式

以 TOML 为例：

1. 新建 `cfg_tool/toml.py`，实现 `TomlError`、`TomlFile`（同一组方法）、
   `TOML_USAGE`、`_toml_main`。
2. 在 `cfg_tool/cli.py` 的 `CFG_USAGE` 增加一行，并在 `main()` 增加懒加载分支。
3. 在 `05.cfg.sh` 的 `cfg_*` 中增加 `toml)` case，并加 `toml_*` 包装。
4. 在 `05.cfg_demo.sh` 增加 `toml_setup`、`toml_test_*`、`run_toml`。
5. 跑第 8 节的验证命令，确认 147 个旧用例仍通过。

这样新增格式不会影响已有格式，也不会让入口文件重新变大。
